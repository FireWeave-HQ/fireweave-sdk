Which CI checks are valid

A check is valid when it fails for a real problem. The fixes below are on this branch, not on main yet.

Valid — keep them

  • Node 24, Bun, Deno 2.x, Web, Go, Java, Rust, Dart. Each builds that SDK and runs its tests. Bun and Deno only smoke-test the Node package, because they cannot run the full Node suite.
  • Swift line length. Real failure: lines over 100 characters. The formatter wrapped them. That commit is on this branch.
  • Python unused imports. Valid. Passes on current main. Older pull requests failed on three unused imports in test_control_points.py. Those imports are already gone.
  • Languages agree, fake server, examples, docs links, workflow file check, license check. Each tests one real thing.
  • Package build for Node, Python, Go, and Java. Valid. Does not publish. Web and Rust dry runs are now in the same job.
  • rustls. Valid. The Rust HTTP client ureq ships it. The lockfile is now 0.23.45. Do not merge pull request #19 as it stands; that bump sits on an older branch.

Fixed on this branch

  • CI now runs on main. Both workflow files watched master. Pushes to main never started CI or Security. They now watch main.
  • Secret scan still runs, and test strings no longer fail it. gitleaks.toml allows Swift tests, Dart tests, contracts/errors.json, and the fake key project-api-key_ci. A real key outside those paths still fails. The same scan, including old commits, now reports no leaks.
  • Deno nightly is gone. Deno 2.x stays on every pull request. There is no weekly Deno job.
  • Node 20.20.0 is the oldest Node job. The setting 20 was installing the newest 20.x. The Node job and the examples job now install 20.20.0, which is the floor the package states.
  • New-dependency check fails if it cannot look. If GitHub’s compare API is down, that job used to log a warning and pass. It now fails.
  • Web install uses the lockfile publish uses. The pull-request job runs bun install --frozen-lockfile.
  • Release verify runs the language tests it used to skip. Besides Node, Python, Go, Java, and the examples, it now runs Rust, Swift (including the line-length check), Dart, and Web. Secret scan and dependency bugs stay in the Security workflow.
  • Web and Rust get a package dry run on pull requests. Nothing is published. Dart already had its own. Swift still has no package dry run on pull requests, because a Swift release is a mirror push, not a package file.

Not changed Support choice

  • Go 1.25.13. This is the oldest Go the module allows, not a library the SDK ships. The bug list treats it as if every user builds with exactly that Go. Raising it to 1.26.9 would drop 1.25. That was not done. No second Go bug scanner was added.

Do not

  • Do not add another Go bug scanner.
  • Do not add a second Swift style tool.
  • Do not turn the secret scan off.
